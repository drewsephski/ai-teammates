# Pulse reliability review — 2026-11-01

Reviewed the Pulse implementation merged at `3bfd057`, on clean `main` at
`db4ed7d`. Scope: the existing Google Sheets project-coordinator workflow.

- Reads resolve the numeric tab identity from metadata, then request an explicit
  bounded range. Missing, malformed or mismatched identities fail closed.
- Ambiguous or stale mappings return no task conclusions or writable addresses.
  The person must confirm a current header or valid column letter.
- Edits use one RAW batch of exact cells. Server-owned approval preconditions
  bind the tab ID, headers, task row identity and expected values. Krafty writers
  serialize by spreadsheet, check immediately before one update, then verify
  the receipt and independently read back changed and preserved cells. Unknown
  outcomes never automatically repeat the write. Old approvals without these
  preconditions require a new review and approval.

## Checks and limits

Lint, typecheck, full tests (**1,072 passed**) and production build passed.
The tests include stale headers/values, moved tasks, replaced tabs, malformed
provider responses, duplicate approvals, simultaneous writes, lock loss,
collateral changes and timeout-after-commit behavior.

Remaining limits: Google values updates have no atomic compare-and-swap, so a
human edit can race the last read and write. Large reviews stop at 5,000 rows;
unsafe or oversized edit proofs are refused. This is not a deployed Trigger.dev
or signed-in app end-to-end run. The worker needs an explicit deploy after merge;
no deployment was performed. The sample sheet and test connection remain for
inspection.
