# Krafty marketing audit validation — 2026-10-14

The supplied review identified four actionable gaps, all confirmed against the
live site. The working tree now addresses them. These changes have not been
deployed; the public site still serves the previous version.

## Findings

| Finding | Validation | Resolution |
| --- | --- | --- |
| Missing security headers | Anonymous GETs to the homepage, legal pages, auth pages, protected routes and a 404 lacked all five reported headers. | Global CSP baseline, `nosniff`, framing denial, referrer policy and production HSTS in `next.config.ts`. Clerk supplies a fresh nonce-based script policy through `proxy.ts`. |
| Pricing gated for visitors | Anonymous `/pricing` returned 307 to sign-in. Both the dashboard layout and pricing page call `auth.protect()`; the proxy did not impose this guard. | The proxy sends visitors to `/#pricing` with a temporary redirect. Authenticated visitors continue to the existing plans/billing page. The homepage's footer pricing link now reaches its public pricing section for visitors. |
| Missing crawler files | `/robots.txt` and `/sitemap.xml` returned 404. | Added Next.js metadata routes. The sitemap lists `/`, `/privacy` and `/terms`. Robots rules exclude auth and app URLs; `X-Robots-Tag: noindex, nofollow` also covers app/auth/API responses. |
| Oversized logo fallback | Raw HTML used `w=3840` for a 90px logo. | Fixed display dimensions generate 96px and 256px variants, with a 256px fallback for high-DPI displays. |
| Clerk preload warning | The observed Clerk UI preload uses `as="script"`; it is generated by the SDK. The reported protect loader warning was not reproduced. | No bootstrap changes. Removing SDK-generated protection resources could affect authentication. |
| WebGPU probe failure | Not reproduced during this validation. The supplied review attributed it to Clerk's protection script under headless Chrome. | No product fix established. |

The logo finding needs a qualification: modern browsers choose from `srcset`
even when JavaScript is disabled. The large fallback affects clients that ignore
`srcset`; it is not inherently a no-JavaScript problem.

Missing headers are defense-in-depth gaps, rather than evidence that an injection,
cookie theft or downgrade attack has occurred. Robots rules control cooperative
crawlers, not access to private data; existing authentication remains in place.

## Policy and compatibility

- Clerk's strict CSP supplies a fresh script nonce. The root layout renders per
  request and passes that nonce to Clerk and the theme provider. Legal documents
  therefore render dynamically too; metadata routes and static assets remain static.
- Production does not allow JavaScript `unsafe-eval`. WebAssembly compilation is
  allowed for Rive and syntax highlighting. Clerk retains inline style support.
- HTTPS attachments, media, fonts and previews, blob workers, and HTTPS/WSS
  connections remain allowed for existing chat, payment and realtime features.
- HSTS is production-only, with a one-year lifetime for the current host. It does
  not include subdomains or opt into browser preload lists.
- The pricing redirect is temporary because the destination depends on login
  state. The dashboard layout and billing page retain their authentication guards.
- No dependencies, environment variables, database schemas or Trigger.dev tasks
  were changed by this audit.

## Verification

- `pnpm typecheck`: passed.
- `pnpm test`: 194 passed, none failed or skipped.
- Changed-file ESLint, Prettier and `git diff --check`: passed.
- `pnpm lint`: failed on 15 existing errors and 9 warnings in untouched files,
  including generated AI Elements/UI components, `hooks/use-mobile.ts` and
  `trigger/example.ts`.
- `pnpm build`: passed using Turbopack and the custom-server bundle in a temporary
  source copy, without disturbing the existing development server.
- The production server on port 3002 passed anonymous HTTP checks for the
  homepage, pricing, both crawler files, both legal pages, both auth pages,
  workspace, usage, a chat URL and a 404. All expected security headers were
  present, auth/app responses had `noindex`, and public pages did not.
- Every executable script in the returned homepage, legal, auth and 404 HTML
  had the response's nonce. Each document request produced a different nonce.
  Static JS, the original logo and its optimized fallback passed HEAD checks.
- A browser check using child documents that inherit the page's policy rejected
  an unnonced inline script and accepted the same script with the matching nonce.
  WebAssembly compiled successfully.
- Desktop and 375px checks found no horizontal overflow or broken images. The
  mobile menu opened, closed with Escape, and closed after selecting Pricing.
  Browser navigation to `/pricing` reached `/#pricing`.

Clerk's production keys reject `localhost` with an explicit HTTP-origin error.
The SDK script loaded, but full sign-in, checkout and authenticated dashboard/
desktop journeys could not be completed locally. Those journeys still need
verification on the allowed hosted domain before calling this release validated.
The production-origin error is an environment limitation, not a CSP violation.
